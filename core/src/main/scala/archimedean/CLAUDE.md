# CLAUDE.md

This file provides guidance to [Claude Code](https://claude.com/product/claude-code) when working with code in this directory.
It is not intended for human eyes.

## Instructions

- This package contains _Archimedean_ variants of type classes from the
  [ordered](../ordered) package, for structures that support rounding to integer
  values (the subring generated by `one`). Lawful instances exist exactly for
  Archimedean structures — those with no infinite or infinitesimal elements.
- `Archimedean` is the root (extends `Ordered`); the package is a FULL mirror
  of [ordered](../ordered) — one `ArchimedeanFoo` per `OrderedFoo`, where
  `ArchimedeanFoo` extends the Archimedean versions of `OrderedFoo`'s ordered
  parents, plus `OrderedFoo` itself. The same rules apply as in
  [../CLAUDE.md](../CLAUDE.md) and [../ordered/CLAUDE.md](../ordered/CLAUDE.md).
- One deliberate asymmetry: `ArchimedeanDifferenceSemigroup` extends
  `ArchimedeanDifference` and `ArchimedeanQuotientSemigroup` extends
  `ArchimedeanQuotient`, even though the ordered equivalents skip
  `OrderedDifference`/`OrderedQuotient`. This is required so `frac` (and the
  subtype relation) propagates up the spine.
- `floor` and `ceil` are the primitives. `ceil` gains a derived default
  (`-⌊-x⌋`) only at `ArchimedeanAdditiveInverse`; instances without negation
  (e.g. unsigned/monus types) must implement both.
- Each op lives at the minimal structure that can express it:
  - `floor`, `ceil`, `isIntegral`, `isFractional` — `Archimedean` (order only)
  - `truncate` — `ArchimedeanAdditiveIdentity` (needs `zero`)
  - `ceil` default — `ArchimedeanAdditiveInverse` (needs `negate`)
  - `frac` — `ArchimedeanDifference` (needs `subtract`)
  - `round` — `ArchimedeanDifferenceSemiring` (needs `one`, `add`, `subtract`)
  - `remainder`, `floorRemainder`, `euclideanRemainder` —
    `ArchimedeanQuotientRing` (needs `div`, `sign`, `abs`)
- The remainder family always rounds the quotient to an integer value first, so
  it stays meaningful on fields (where `mod` is trivially `zero`). On types
  whose `div` already truncates, `remainder` coincides with `mod`.
- Do NOT add degenerate instances for discretely-ordered types (`Int`,
  `BigInt`, etc.) where `floor` would be the identity.
